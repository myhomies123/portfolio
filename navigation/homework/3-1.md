## Popcorn

```python
# CODE_RUNNER: UESL 3.1 Popcorn - Keep the checkpoint
stars = 8
checkpoint_stars = stars
stars = stars + 4
print(stars)
print(checkpoint_stars)
```

Prediction: `stars` will be 12 and `checkpoint_stars` will remain 8.

Actual output:

```text
12
8
```

The values differ because `checkpoint_stars = stars` stores the value that existed at the time of that assignment. Updating `stars` later does not automatically update the checkpoint.

## Homework

```python
# CODE_RUNNER: UESL 3.1 Homework - Star counter with a bonus
game_title = "UESL Star Trail"
reduced_motion = True

level_one_stars = 12
level_two_stars = 18
level_three_stars = 10

total_stars = level_one_stars + level_two_stars + level_three_stars

print(game_title)
print("Reduced motion:", reduced_motion)
print("Original total:", total_stars)

level_two_stars = level_two_stars + 5
print("Stored total after bonus:", total_stars)

total_stars = level_one_stars + level_two_stars + level_three_stars
print("Recalculated total after bonus:", total_stars)
```

Prediction: The original total is 40. After the level-two bonus, the stored total is still 40 until it is recalculated; the updated total is 45.

Actual output:

```text
UESL Star Trail
Reduced motion: True
Original total: 40
Stored total after bonus: 40
Recalculated total after bonus: 45
```

## Tests

### Test 1 — bonus of 5

The homework code above starts with fresh values and produces 40, 40, then 45. This confirms that assignment stores a result rather than creating a live formula.

### Test 2 — bonus of 0

```python
# CODE_RUNNER: UESL 3.1 Test - Zero bonus
level_one_stars = 12
level_two_stars = 18
level_three_stars = 10
bonus = 0

total_stars = level_one_stars + level_two_stars + level_three_stars
print("Original total:", total_stars)

level_two_stars = level_two_stars + bonus
print("Stored total after bonus:", total_stars)

total_stars = level_one_stars + level_two_stars + level_three_stars
print("Recalculated total after bonus:", total_stars)
```

Actual output:

```text
Original total: 40
Stored total after bonus: 40
Recalculated total after bonus: 40
```

With a zero bonus, the level value never changes, so all three totals remain 40.

## Design Thinking

Player need: Some players may prefer less on-screen motion while playing a game.

Goal: Make a game-state prototype that clearly stores both a player setting and star progress.

Setting considered: I used the Boolean `reduced_motion = True` because it clearly represents an on/off player choice without collecting private player information.

Prototype: I built a star counter with separate level variables, a stored total, and a recalculated total after a bonus.

Test and revision: I tested both a bonus of 5 and a bonus of 0 with fresh starting values. The tests show why the total must be explicitly recalculated after a level changes. Reduced motion should remain the player's choice because accessibility settings work best when the player can choose the experience that is comfortable for them.
